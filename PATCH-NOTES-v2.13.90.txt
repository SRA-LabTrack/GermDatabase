GERMPLASM SCROLL CRASH HOTFIX
================================

Observed symptom
----------------
When the Germplasm Collection cards entered the viewport, React could fall into the
"The app shell could not start cleanly" recovery screen.

Root cause
----------
The v2.13.88 workbook update intentionally stored provenance metadata under
details_json.origin. The runtime expandRecord() function spread details_json directly
onto the visible record. That nested `origin` object could overwrite the normal scalar
Country field named `origin`.

When a Germplasm card became visible, getLocalRecordPreview() loaded a cached/offline
expanded snapshot. React then attempted to render that object as the Country text,
which can throw and trigger the root error boundary.

Fix
---
- Flatten/sanitize nested origin metadata before returning expanded records.
- Sanitize stale IndexedDB/offline preview snapshots without deleting them.
- Render Germplasm card preview values through a safe text formatter.
- Preserve Country, breeder, collection scope, species, genetic background and other
  new workbook attributes.
- No Appwrite records are deleted or rewritten.
- No schema/setup command is needed.
